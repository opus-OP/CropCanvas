# ТЗ: десктоп-приложение для сборки шортсов по шаблону

## 1. Цель проекта
Приложение с GUI, которое избавляет от ручной пересборки одного и того же макета шортса в видеоредакторе. Пользователь:
1. загружает один исходный видеофайл,
2. на превью этого видео двигает/ресайзит прямоугольники — они определяют, какая часть кадра попадает в каждую зону шаблона,
3. видит живой предпросмотр итогового шаблона,
4. жмёт «Рендерить» — на выходе готовый mp4.

## 2. Платформа и стек
- **ОС:** Arch Linux, **Wayland**.
- **Стек приложения:** Electron (Chromium + Node.js) — живой предпросмотр реализуется через HTML5 `<video>`/`<canvas>` с CSS-позиционированием и/или canvas-рисованием кропнутых регионов кадра.
- **Рендер финального ролика:** ffmpeg, вызывается как дочерний процесс (`child_process`).
- **Запуск на Wayland:** через `run.sh`, стартующий Electron с флагами `--ozone-platform=wayland --enable-features=UseOzonePlatform` (чтобы не заворачивать окно через XWayland).
- Всё работает локально, без интернета.

## 3. Ключевая механика (важно!)
Всё содержимое шаблона (кроме статичного PNG-оверлея) — это **один и тот же исходный видеофайл**, который проигрывается **синхронно и целиком** во всех зонах одновременно. Разные зоны показывают не разные файлы и не разные отрезки по времени, а **разные вырезанные области кадра** этого одного видео в один и тот же момент времени (как несколько окон, смотрящих в разные углы одного и того же кадра).

Поэтому редактируется не "куда на выходе положить зону", а "какую часть исходного кадра взять для зоны" — через прямоугольники, накладываемые на превью исходного видео.

## 4. Функциональность MVP

### 4.1 Загрузка исходника
- Кнопка «Загрузить видео» — один файл на весь рендер (диалог выбора файла).
- Поддерживаются любые форматы, которые понимает ffmpeg (mp4, mov, mkv и т.д.).

### 4.2 Разметка кадра источника (главный экран приложения)
- Панель с превью загруженного видео (воспроизведение/пауза/перемотка).
- Поверх превью отрисованы **N прямоугольников** — по одному на каждую видео-зону текущего шаблона.
  - Для шаблона 1 (по описанию): `model_fullscreen`, `top_filler`, `bottom_1`, `bottom_2`, `bottom_3` — 5 прямоугольников, у каждого своя подпись/цвет.
  - Для шаблона 2 — свой набор (уточняется отдельно, механика та же).
- Каждый прямоугольник:
  - двигается мышкой по кадру источника,
  - меняет размер за угловые/боковые маркеры,
  - не обязан совпадать по пропорциям с выходной зоной — при несовпадении применяется авто-кроп по центру под пропорции выходной зоны (если понадобится другая логика — обсуждается отдельно).
- Позиции прямоугольников для каждого шаблона сохраняются в локальный JSON между запусками (`config/template1.json`, `config/template2.json`), чтобы не настраивать заново каждый раз.

### 4.3 Холст вывода (предпросмотр финального ролика)
- Отдельная область — вертикальный холст 1080×1920 с **фиксированной раскладкой** зон текущего шаблона (позиции и размеры зон на выходе заданы самим шаблоном, пользователь их не двигает — двигаются только прямоугольники-источники в п. 4.2).
- Каждая выходная зона в реальном времени показывает содержимое своего crop-прямоугольника из исходного видео, отмасштабированное под размер зоны.
- Статичный оверлей (иконка Twitch + текст, один PNG с альфа-каналом) отображается поверх всех зон.
- Живой предпросмотр = синхронное воспроизведение одного видео с разными crop-окнами в реальном времени; то, что видно тут, должно совпадать 1:1 с финальным рендером.

### 4.4 Переключение шаблонов
- Кнопки/вкладки «Шаблон 1» / «Шаблон 2» переключают: набор и расположение выходных зон + количество и дефолтные позиции crop-прямоугольников на источнике.
- Именованные пользовательские пресеты не нужны, только эти 2 фиксированных шаблона.

### 4.5 Рендер
- Кнопка «Рендерить»:
  1. Для каждой выходной зоны строится ffmpeg-граф: `crop` исходника по координатам прямоугольника → `scale` под размер выходной зоны → `overlay` на холст 1080×1920 в нужной позиции (через `split` исходного потока на N копий, поскольку одно и то же видео используется многократно).
  2. PNG-оверлей накладывается поверх всего последним слоем.
  3. Аудио берётся напрямую из единственного исходника (выбор не нужен — дорожка одна).
  4. Длительность ролика = длительность исходного файла целиком.
- Индикация статуса рендера (минимум — «Рендер идёт…», по возможности % по stderr ffmpeg).
- Выходной формат: mp4, H.264 + AAC, 1080×1920, fps — как у исходного файла.
- Готовый файл сохраняется в папку по выбору пользователя, имя — с таймстампом по умолчанию.

## 5. Нефункциональные требования
- Запуск: `./run.sh` — при первом запуске делает `npm install`, если нет `node_modules`, затем `npx electron . --ozone-platform=wayland --enable-features=UseOzonePlatform`.
- Системные зависимости (ставятся заранее пользователем через pacman): `nodejs`, `npm`, `ffmpeg`.
- Никаких фоновых служб, автозапуска, телеметрии.

## 6. Структура проекта
```
/main.js              — Electron main process: окно, файловый диалог, вызов ffmpeg
/preload.js           — IPC-мост между renderer и Node
/renderer/index.html  — разметка: панель источника с прямоугольниками + холст вывода
/renderer/style.css   — стили прямоугольников, холста, панели управления
/renderer/app.js      — drag&resize прямоугольников, синхронное превью, запрос рендера
/config/template1.json
/config/template2.json — дефолтные/сохранённые координаты прямоугольников по шаблонам
/assets/overlay.png    — оверлей иконка+текст по умолчанию
/run.sh                — скрипт запуска под Wayland
/package.json
```

## 7. Вне рамок MVP (сознательно не делаем сейчас)
- Конструктор шаблонов с нуля (произвольное число зон, шаблоны >2)
- Именованные пользовательские пресеты / библиотека шаблонов
- Работа с несколькими разными исходными файлами одновременно
- Нарезка по времени (разные отрезки видео в разных зонах)
- Пакетный рендер по папкам за один запуск
- Переходы/анимации между зонами
- Что-либо кроме фиксированного PNG-оверлея (без динамических субтитров и т.п.)

## 8. Критерии готовности (Definition of Done)
- `./run.sh` запускает приложение на Arch/Wayland без ошибок и без XWayland-костылей.
- Можно загрузить один видеофайл и переключаться между 2 шаблонами.
- На превью источника можно двигать/ресайзить прямоугольники, изменения сразу видны на холсте вывода.
- Холст вывода в реальном времени показывает то, что реально попадёт в рендер (совпадение кропа/масштаба/позиции 1:1).
- Оверлей PNG корректно накладывается поверх всех зон.
- Рендер по кнопке создаёт корректный mp4 1080×1920 с нужными кропами, раскладкой, оверлеем и звуком.
- Успешный рендер подряд минимум 5 разных исходных файлов без падений.
